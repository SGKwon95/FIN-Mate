## 1. FIN-Mate 프로젝트 (가장 많이 나올 것)

### RAG 파이프라인

- pgvector로 벡터 검색을 직접 구현하셨는데, Chroma나 Qdrant 같은 전용 벡터 DB 대신 pgvector를 선택한 이유가 있나요?
- 청킹 전략을 "제N조 → 항(①②③)" 계층 구조로 설계한 이유가 뭔가요? 고정 길이 청킹과 비교해서 어떤 차이가 있었나요?
- Hybrid Search(BM25 + Vector)를 도입한 계기가 뭔가요? 실제로 어떤 쿼리 유형에서 효과가 있었나요?
- RRF(Reciprocal Rank Fusion) k=60으로 설정한 기준이 있나요?
- `quality_score` 기반 Re-ranking이 Cross-encoder와 다른 점은 뭔가요? 왜 Cross-encoder 대신 이 방식을 선택했나요?
- 2단계 캐싱(Exact hash + Semantic 0.95)에서 임계값 0.95는 어떻게 정했나요? 너무 높으면 캐시 히트율이 낮고, 낮으면 다른 질문의 답을 반환할 텐데요.
- LLM Hallucination을 줄이기 위해 시스템 프롬프트를 어떻게 설계했나요? 구체적인 예시를 들어줄 수 있나요?
- RAGAS를 직접 구현하셨는데, Context Relevance, Faithfulness, Answer Relevance를 각각 어떻게 측정했나요?

### Kafka 타행이체

- 9단계 비동기 파이프라인을 설계할 때 단계를 왜 9개로 나눴나요?
- at-least-once와 exactly-once의 차이가 뭔가요? 금융 시스템에서 at-least-once를 선택하고 idempotency key로 보완한 이유는요?
- RF=3, min.insync.replicas=2로 설정했는데, 브로커 2개가 동시에 내려가면 어떻게 되나요?
- 타행이체는 비동기, 자행이체는 동기로 처리를 분리한 기준이 뭔가요?
- k6 과부하 테스트에서 "DB 행 락 병목"이 발견됐다고 하셨는데, 어떻게 발견했고 어떻게 해결하셨나요?

### Observability

- OpenTelemetry에서 Trace, Metric, Log를 각각 어디에 어떻게 활용했나요?
- Arize Phoenix로 RAG 품질을 모니터링한다고 하셨는데, 실제로 어떤 문제를 발견해서 개선한 사례가 있나요?
- Prometheus가 OTel 트레이스에 노이즈를 만든 문제가 있다고 들었는데, 어떻게 해결했나요?
